# Contributing

Thank you for taking an interest in Uslu Medya's work. We value contributions that are clear, relevant, and easy for the team to maintain.

## Discuss the work first

This repository is primarily maintained by our internal team. If you are an external contributor, please open a proposal or email [usluyapimorg@gmail.com](mailto:usluyapimorg@gmail.com) before starting implementation. Wait for a maintainer to confirm the scope.

Small factual or typographical corrections may be submitted directly. Please use [private security reporting](SECURITY.md) for vulnerabilities or exposed information.

## What belongs here

- Accurate improvements to the GitHub profile and service descriptions.
- Clearer documentation and collaboration guidelines.
- Corrections to links, accessibility text, or visual presentation.
- Improvements to this repository's issue and pull request templates.

Application bugs and feature requests belong in the relevant project's repository. Business inquiries belong in [email](mailto:usluyapimorg@gmail.com).

## Preparing a change

1. Read the [governance guidelines](GOVERNANCE.md) and [code of conduct](CODE_OF_CONDUCT.md).
2. Create a branch for a single, agreed change. External contributors can use a fork once the scope is confirmed.
3. Keep public-facing content in English. Preserve proper names and official account handles.
4. Use accurate descriptions of our services and experience. Discuss new claims, technologies, and project listings with a maintainer.
5. Include only material you have permission to contribute. Check permissions and attribution when reusing code, images, music, or other assets.

Never include secrets, customer records, production exports, private client assets, cPanel credentials, mailbox contents, or unredacted infrastructure details. Use synthetic examples and redact sensitive screenshots.

## Validate what changed

This is a profile and documentation repository; it has no application build or runtime dependencies.

- Preview Markdown using a renderer compatible with GitHub.
- Check changed internal links and external destinations.
- For visual changes, inspect the banner at wide and narrow sizes and keep useful alternative text.
- For template changes, check YAML syntax and GitHub form requirements.
- Read the rendered result for spelling, readability, and factual accuracy.

If a check cannot be completed, explain the limitation in the pull request. For changes to a separate software project, follow that project's setup and validation instructions.

## Open a pull request

Describe the purpose, agreed scope, and validation. Include a screenshot for visible layout changes where useful. Identify anything that needs owner approval, such as service claims, contact information, or policy changes.

A maintainer reviews the work and may ask for revisions. Acceptance and merge authority follow [GOVERNANCE.md](GOVERNANCE.md).
