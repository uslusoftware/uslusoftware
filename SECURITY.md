# Security

Please report vulnerabilities and exposed information privately so we can assess the concern without increasing the exposure.

## Where to report

Email **[usluyapimorg@gmail.com](mailto:usluyapimorg@gmail.com)** with the subject **Security report — repository or service name**.

For the initial message, describe the affected repository or service and summarize the concern. Do not send passwords, tokens, customer records, mailbox contents, or a working exploit containing sensitive data. If more sensitive evidence is needed, ask us to agree on a suitable way to share it.

Do not use public issues or pull requests to disclose vulnerabilities, credentials, or private infrastructure details. If a repository explicitly offers GitHub private vulnerability reporting, that channel may also be used.

## Helpful information

- The affected repository, file, page, or service.
- A concise description of the issue and potential impact.
- Minimal, safe reproduction steps, if available.
- Sanitized screenshots or logs with secrets and personal information removed.
- When you observed the issue and how we can contact you.

## Scope and support

This repository contains profile content, documentation, and collaboration templates. Relevant concerns include exposed secrets, malicious links, and accidentally published confidential material.

For another Uslu Medya project, consult that repository's security policy and supported versions first. If you cannot find a reporting route, use the email above and identify the project. This profile does not establish a support lifecycle for other software or services.

## Coordination

We assess reports, request clarification where needed, and coordinate remediation and any appropriate disclosure. Response and resolution times depend on severity and available information; we do not publish a guaranteed response time or a bounty program here.

Please limit investigation to systems you own or are explicitly authorized to test. Avoid accessing other people's data, interrupting services, or using discovered credentials.

## If you accidentally publish a secret

Notify the team privately and arrange prompt revocation or rotation through the appropriate service owner. Identify affected systems and remove the exposed material. Deleting the latest file does not remove copies from Git history, forks, caches, or logs; coordinate further cleanup with the owner.
